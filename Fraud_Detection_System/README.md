# 🛡️ Fraud Detection Pipeline

**Project 2 — Supervised Learning** (DecodeLabs Data Science Industrial Training Kit, Batch 2026)

A multi-page Streamlit dashboard that builds, tunes, evaluates, and serves
classification models to detect fraudulent credit card transactions in a
highly imbalanced dataset — using a **leak-free** SMOTE + Scikit-learn
pipeline, with trained models persisted to disk.

Built by **Kinza Arshad** — Data Science Undergraduate, KFUEIT.

---

## Why this project matters

Fraud datasets are extremely imbalanced (here, ~0.17% fraud). A model that
predicts "legitimate" every single time scores 99.8% accuracy while
catching zero fraud. This project is built specifically to avoid that trap,
and the more subtle **data leakage** trap (applying SMOTE/scaling before
the train/test split), by:

- Splitting **before** any resampling or scaling
- Placing `StandardScaler` and `SMOTE` **inside** an `imblearn.pipeline.Pipeline`
- Tuning hyperparameters with `GridSearchCV` + `StratifiedKFold`, so
  resampling happens fresh inside every cross-validation fold
- Evaluating with **Precision, Recall, F1, and ROC-AUC** — never raw accuracy

**Why `utils/` vs `components/`?** `utils/` holds logic that never imports
Streamlit — it's plain Python you can unit test with `pytest` outside the
app (see `tests/test_pipeline.py`, which passes with zero Streamlit
installed). `components/` wraps that logic in Streamlit rendering calls.
This separation is standard practice in production ML apps and is worth
being able to explain in an interview.

## Setup Instructions

1. **Clone / download this folder**

2. **Create a virtual environment (recommended)**
   ```bash
   python -m venv venv
   source venv/bin/activate      # Windows: venv\Scripts\activate
   ```

3. **Install dependencies**
   ```bash
   pip install -r requirements.txt
   ```

4. **Add the dataset** (see below) — or skip this step to run instantly on
   built-in synthetic demo data.

5. **Run the app**
   ```bash
   streamlit run app.py
   ```

6. Open the local URL Streamlit prints (usually `http://localhost:8501`).

7. **Run the tests** (optional but recommended before you push to GitHub)
   ```bash
   pytest tests/
   ```

## Dataset

This project is designed for the **Credit Card Fraud Detection** dataset:

- Source: Kaggle — [`mlg-ulb/creditcardfraud`](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud)
- 284,807 transactions, 492 fraud (0.17%), 30 features (`Time`, `V1`–`V28`, `Amount`) + `Class`

**Steps:**
1. Download `creditcard.csv` from the Kaggle link above (requires a free Kaggle account).
2. Place it at `data/raw/creditcard.csv`.
3. Restart the app — it auto-detects the real file (`data/raw/fraud_dataset.csv` also works as a filename).

> If the real file is missing, the app automatically generates a synthetic
> dataset with the identical schema and imbalance ratio, so you (or anyone
> reviewing your portfolio) can still run and demo the full app without
> downloading anything. A banner on the Data Overview page always tells you
> which dataset is active.

## How the pieces fit together at runtime

1. **Preprocessing page** cleans the data, does a stratified train/test
   split, previews SMOTE, and writes `data/processed/processed_data.csv`.
2. **Model Training page** builds an `imblearn.Pipeline` per model (scaler
   + SMOTE + classifier), tunes it with `GridSearchCV`, evaluates it on the
   untouched test set, and — if you leave "Save trained models" checked —
   writes `models/logistic_regression.pkl` / `models/random_forest.pkl`
   (plus `models/scaler.pkl` for the Logistic Regression scaler).
3. **Model Comparison page** lets you save whichever model wins on
   ROC-AUC as `models/best_model.pkl`.
4. **Predictions page** uses whatever's trained in the current session —
   and if you restart the app before retraining, it automatically falls
   back to loading the `.pkl` files from `models/`, so predictions still
   work.

## How to Demo This in an Interview

1. Open **Dashboard** → explain the problem (imbalanced classification).
2. **Data Overview** → point out the 0.17% fraud rate and why accuracy is misleading.
3. **Preprocessing** → explain *why* SMOTE is applied only to the training fold.
4. **Model Training** → train both models, explain GridSearchCV + StratifiedKFold.
5. **Model Comparison** → compare Precision/Recall/ROC-AUC, discuss the trade-off
   (Random Forest usually wins here — no scaling sensitivity, handles non-linear splits).
6. **Predictions** → load a random fraud example, show the probability output,
   and explain the classification threshold trade-off (Settings page).
7. Mention the `utils/` vs `components/` split and the `tests/` folder —
   this signals you think about code structure and testability, not just
   getting a model to run once in a notebook.
